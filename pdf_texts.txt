Composants de l'Architecture Applicative à Définir 
●​ Localisation du Moteur d'Acheminement (Routing Engine) : L'architecture doit 
statuer sur l'endroit où s'exécute la logique de simulation IP (décrémentation du TTL, 
vérification du sous-réseau, recalcul du checksum). S'exécute-t-elle côté client 
(navigateur) ou côté serveur (Backend) ? 
●​ Couche de Communication Multi-utilisateurs : Le document exige une 
visualisation en temps réel pour une application multi-utilisateurs. Le protocole 
HTTP/REST standard est inadapté. L'architecture doit spécifier le protocole 
bidirectionnel utilisé (WebSockets, SSE) pour pousser les mises à jour de topologie 
aux autres clients. 
●​ Gestion de l'État (State Management) : La topologie réseau est un graphe 
complexe. Le schéma d'architecture doit expliciter le flux strict de synchronisation 
entre la base de données PostgreSQL , la mémoire du backend, le gestionnaire 
d'état du frontend (ex: Redux, Pinia) et le canevas de la bibliothèque vis.js. 
●​ Stratégie de Verrouillage Concurrentiel : Le schéma architectural doit démontrer 
comment une collision d'édition est gérée techniquement (Verrouillage optimiste via 
numéro de version vs verrouillage pessimiste) si deux techniciens modifient la même 
interface de routeur à la même milliseconde. 
●​ Sécurité et Isolation (Multi-tenancy) : Comment les scénarios réseau sont-ils 
isolés logiquement dans la base de données PostgreSQL pour respecter la 
contrainte d'authentification et éviter les fuites de données entre utilisateurs ?
